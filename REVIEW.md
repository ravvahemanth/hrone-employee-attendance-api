# REVIEW.md

## Confirmed Starter Defects in `app/main.py`

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` L72-74 | Returns static `{"status": "ok"}` without pinging MongoDB. Contract requires 503 if database is unreachable. | Stop MongoDB service; `GET /health` returns 200 instead of 503. | Wrapped `db.command("ping")` in try-except block, raising `HTTPException(503)` on connection failure. |
| 2 | `list_employees()` L93 | Skip calculation was `skip = page * page_size`, which skips page 1 entirely. | Requesting `page=1, page_size=20` returns items 21–40 instead of 1–20. | Changed formula to `skip = (page - 1) * page_size`. |
| 3 | `list_employees()` L94 | Total count was `db.employees.count_documents({})`, ignoring the applied `department` filter. | Filter by `department=Engineering` on a DB with 50 total employees (10 in Eng); response returns `total: 50`. | Changed to `db.employees.count_documents(q)` so total reflects the filtered subset. |
| 4 | `list_employees()` L95 | Missing mandatory sort by `emp_code` ascending. | Fetched employees are returned in non-deterministic natural order. | Added `.sort("emp_code", 1)` to the query cursor. |
| 5 | `create_employee()` L79-83 | Check-then-insert race condition (`find_one` followed by `insert_one`). | Two concurrent requests with the same `emp_code` both pass the check and both insert documents or fail without proper error code. | Enforced database unique index on `emp_code` and caught `DuplicateKeyError`, converting it to HTTP 409. |
| 6 | `create_employee()` L82 | Used naive local time `datetime.now()` for `created_at` instead of UTC. | Stored timestamp in MongoDB reflects server local time zone rather than UTC BSON date. | Changed to `datetime.now(timezone.utc).replace(microsecond=0)`. |
| 7 | `create_employee()` L84-85 | Returned MongoDB document directly where `created_at` serializes as ISO string rather than epoch milliseconds. | Client receives string timestamp instead of integer epoch ms. | Implemented `serialize_employee` helper returning integer epoch milliseconds for `created_at`. |
| 8 | `EmployeeIn` model L53-60 | Missing validation constraints: no regex for `emp_code`, email format, or date format; allowed `shift_start == shift_end`. | Sending invalid code or equal shift times (e.g., `09:30` and `09:30`) succeeded with 201 instead of 422. | Added Pydantic field validators matching OpenAPI regex patterns and a model validator ensuring `shift_start != shift_end`. |
| 9 | `punch_in()` L101 | Did not verify employee existence before accessing `emp["shift_start"]`. | Punching in with non-existent `emp_code` threw Python `TypeError`/`KeyError` resulting in HTTP 500. | Added existence check returning HTTP 404 when employee does not exist. |
| 10 | `punch_in()` L102 | Used naive `datetime.fromtimestamp()` converting milliseconds to server's local timezone. | Server running in UTC-5 calculates wrong IST calendar date for punch-in. | Converted epoch ms to UTC datetime and used `astimezone(IST)`. |
| 11 | `punch_in()` L102 | Missing timestamp validation; accepted float, string, or second-scale integers. | Sending `"1783312500000"` or `1234567890` was accepted instead of returning HTTP 422. | Used Pydantic `StrictInt` with range `[100000000000, 4102444800000]`. |
| 12 | `punch_in()` L102-103 | Did not truncate instant to whole seconds before calculation and storage (violates R1). | Timestamps with fractional seconds stored non-truncated microseconds. | Truncated seconds via integer division `(ms // 1000) * 1000` and `replace(microsecond=0)`. |
| 13 | `punch_in()` L103 | Used `ts.date().isoformat()` without accounting for overnight shifts where punch-in before `shift_end` belongs to previous day. | Overnight shift (22:00–06:00) punched in at 01:10 IST was tagged with current date instead of shift start date. | Implemented `get_attendance_date` applying R1 overnight logic. |
| 14 | `punch_in()` L104-105 | Check-then-insert race on `(emp_code, date)` allows concurrent duplicate punch-ins. | Two parallel punch-ins at same instant could both insert records. | Enforced database unique compound index on `(emp_code, date)` and caught `DuplicateKeyError` to return HTTP 409. |
| 15 | `punch_in()` L109 | Allowed arbitrary status values including `ABSENT` and `LEAVE`. | Sending `status="ABSENT"` at punch-in created an invalid punch-in document. | Restricted punch-in status to `PresenceStatusEnum` (`PRESENT`, `WFH`, `ON_DUTY`). |
| 16 | `punch_in()` L119-121 | Added `id` field from MongoDB `_id` and returned datetime objects directly. | Response included internal `id` contrary to contract, and dates were not epoch ms integers. | Removed `id` field and serialized instants as integer epoch milliseconds. |
| 17 | `compute_late_minutes()` L33-37 | Replaced hour and minute on `punch_in` directly, failing for overnight shifts and multi-day differences. | Punching in at 00:30 for a 22:00 overnight shift produced negative diff or wrong day start. | Constructed scheduled shift start using `attendance_date` in IST. |
| 18 | `compute_work_hours()` L40-41 | Used Python built-in `round()` (banker's rounding) rather than arithmetic half-up rounding (violates R4). | An elapsed time producing `8.425` rounded down to `8.42` instead of `8.43`. | Used `decimal.Decimal` with `ROUND_HALF_UP`. |
| 19 | `compute_overtime()` L44-47 | Did not handle overnight shifts; scheduled end was set on `date_str` rather than next calendar day. | Overnight shift ending at 06:00 evaluated `punch_out - end` against previous day 06:00, giving 24+ hours overtime. | Added 1 day to `end_date` for overnight shifts (`shift_end <= shift_start`). |
| 20 | `compute_overtime()` L47 | Did not enforce the mandatory 30-minute minimum threshold (violates R3). | Employee punching out 15 minutes after shift end received 15 overtime minutes instead of 0. | Applied `diff_minutes if diff_minutes >= 30 else 0`. |
| 21 | `list_attendance()` L144-147 | Loaded entire collection into Python memory (`list(db.attendance_logs.find(q))`) and sorted in Python. | On ~100k records, server runs out of memory or blocks event loop for seconds. | Replaced with indexed MongoDB query `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)`. |
| 22 | `list_attendance()` L145 | Sort was only by `date desc`; contract requires secondary sort by `emp_code asc`. | Records on the same date had non-deterministic pagination order. | Added secondary sort on `emp_code: 1`. |
| 23 | `list_attendance()` L130-131 | Missing parameter bounds: no validation that `page >= 1` or `1 <= page_size <= 100`. | Requesting `page_size=1000` or `page=0` returned unbounded data or negative slice indices. | Added FastAPI `Query` validators `ge=1, le=100`. |
| 24 | `list_attendance()` L136-141 | Did not validate that `date_from <= date_to`. | Passing `date_from=2026-07-10&date_to=2026-07-01` executed invalid range without returning HTTP 422. | Added explicit check raising HTTP 422 when `date_from > date_to`. |
| 25 | Database Initialization | Missing index creation at application startup. | Database had only default `_id` index; queries resulted in collection scans (`COLLSCAN`). | Implemented idempotent startup index creation via FastAPI lifespan manager. |

## Inspected Components Found Correct

- **Collection names**: `employees` and `attendance_logs` matched the data model specification.
- **Environment variable names**: `MONGO_URI` and `MONGO_DB` matched the specification.
- **Port and entry point**: `app/main.py` entry point configured for `uvicorn app.main:app --port 8000`.
- **IST offset definition**: `timezone(timedelta(hours=5, minutes=30))` is the correct standard offset for Indian Standard Time.
- **Basic field names**: The core schema field names (`emp_code`, `date`, `status`, `punch_in`, `punch_out`, `work_hours`, `late_minutes`, `overtime_minutes`, `half_day`, `history`) matched `DATA_MODEL.md`.
